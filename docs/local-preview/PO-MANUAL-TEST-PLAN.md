## Pencatatan, triage dan keputusan

- Isi actual result dengan pengamatan spesifik, bukan sekadar “OK”. Pilih PASS/FAIL/BLOCKED/NOT RUN dan sertakan bukti; aktual dan status awal di [JSON](manual-test-results.json) sengaja kosong dari klaim kelulusan.
- P0: hentikan uji yang memperluas kebocoran/privilege; simpan bukti teredaksi. P1: tugas utama/aksesibilitas tidak dapat diselesaikan. P2: gangguan yang punya workaround. P3: kosmetik. Severity adalah panduan triage; catat severity aktual bila ada defect.
- Untuk defect: ID, langkah reproduksi, URL/viewport, expected/actual, screenshot/console teredaksi, sumber image/source, severity, retest dan owner. Jangan memasukkan password, token atau data nyata ke bukti.
- PO memberi keputusan manual setelah menjalankan tes. Nama/tanggal/disposisi PO dan reviewer independen tetap PENDING. PASS manual bukan otomatis DD-001, closure Issue #16, keputusan O04/O05/O06 atau QUAL-002.

Referensi penggunaan alat: [VoiceOver Apple](https://support.apple.com/en-euro/guide/voiceover/vo2682/mac), [Chrome Request conditions](https://developer.chrome.com/docs/devtools/request-conditions). Nama tool DevTools dapat berbeda menurut versi; bila fungsi blokir tidak tersedia, catat subkasus sebagai BLOCKED dan tetap jalankan invalid-route/cursor yang tersedia.
