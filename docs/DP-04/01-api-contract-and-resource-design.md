## 1. Cross-operation API conventions (`API-C01`–`API-C14`)

| ID | Proposed contract | Review boundary |
|---|---|---|
| API-C01 | Use a major path prefix `/api/v1`; additive response fields are compatible, removed/renamed fields or changed semantics need a new major contract and change control. | Exact release/version timeline requires AG-04 review. |
| API-C02 | Use plural resource nouns; `GET` reads, `PUT` expresses idempotent target state, `POST` creates/commands, `PATCH` changes selected fields with preconditions, `DELETE` removes only approved own-resource data. | No `DELETE` endpoint is inferred for historical evidence. |
| API-C03 | JSON request/response for business resources; `application/problem+json` for errors. Declared media types and `Accept` govern content negotiation; unsupported media types/accepts use standard HTTP responses. | Binary media uses separately authorized Storage access; no direct browser core-data writes. |
| API-C04 | Server-issued opaque resource IDs. Client cannot choose Student/owner identity for `/me`; Go derives it from verified identity. Responses expose only fields allowed by role and ownership. | Prevent BOLA/IDOR; see [security](02-authentication-authorization-and-security.md). |
| API-C05 | Validate syntax, shape and field types before domain checks; reject unknown unsafe mutation fields. Error detail identifies safe fields/constraints without leaking unpublished answers, private records or other accounts. | No unapproved domain error-code vocabulary is invented. |
| API-C06 | List responses use an opaque, tamper-resistant cursor and stable sort plus optional `nextCursor`; accepted page size is bounded by server policy. Filters/sort keys are whitelisted and reflected in the response. | No numeric page size or search ranking is approved. Cursor cannot bypass authorization after state changes. |
| API-C07 | `Idempotency-Key` is required for non-idempotent high-risk `POST` commands (attempt start, submission if POST, publish, migration, deletion, revocation). Reuse with same active actor/operation/payload returns the prior result; conflicting reuse returns 409. After deletion acceptance restricts access, a repeated client call is side-effect-free but may receive a safe 403 rather than case detail. Key-record retention follows privacy policy. | Exact key storage/TTL is a technical choice for AG-04; `PUT` also remains semantically idempotent. |
| API-C08 | Mutable versioned Admin resources expose an ETag/version token; `If-Match` protects concurrent `PATCH`/publish/archive. Stale precondition gives 412; domain-state conflict gives 409. | Token format is opaque; no SQL/version-column specification. |
| API-C09 | Every response includes or echoes a request correlation ID. Clients may submit one under validation limits; server generates one otherwise. Logs exclude tokens and personal payloads. | See [observability](05-observability-reliability-and-runbooks.md). |
| API-C10 | Timestamps use RFC 3339 with explicit UTC offset; duration/expiry shown as server-authoritative values. Avoid client clock authority for Attempt expiry or deletion deadlines. | Default Attempt expiry is 24 hours; FA-006 B targets remain 30/30/180 days. |
| API-C11 | Reads may be eventually consistent only when labeled as projections; official command acceptance checks authoritative owner state in its transaction. Completion/grades/pins are returned from committed state. | Path progress preview remains unofficial. |
| API-C12 | Deprecation requires documented replacement, migration guidance, notice and a reviewed compatibility window; no silent behavior change to the approved `/v1` contract. | No numeric deprecation period is invented. |
| API-C13 | Authenticated operations require a verified Supabase token and Go account/role/ownership check. Guest public reads use no Student token; Admin operations require a separate Go-authorized privilege. | Deleting accounts are denied official access even if a token is still valid. |
| API-C14 | Normal archive and exceptional revocation are separate resource actions; migration never follows publish implicitly; unsupported prerequisites and conditional GAP details cannot be accepted through a generic payload. | GAP-001/003/007 remain Open. |

**Response envelope proposal:** A successful single-resource response contains `data` and optional `meta` (including `requestId`, `version` or `ETag` where relevant); list response contains `data[]` and `page.nextCursor`. No wrapper may conceal an HTTP failure. Error body uses `type`, `title`, `status`, safe `detail`, `instance`, `requestId`, and optional `invalidParams[]` with `name`/`reason`. Until AG-04 approves a domain error registry, `type` may be `about:blank`; stable business codes are not fabricated. `Location` identifies a newly created resource where applicable. A successful accepted asynchronous deletion returns a case/state, not a false completed-erasure claim.

## 3. HTTP failure semantics and conditional boundaries

| Status | Contract meaning and example |
|---|---|
| 400 | Malformed JSON/query, invalid cursor syntax or unsupported parameter shape before domain validation. |
| 401 | Missing, invalid, expired or not-yet-valid authentication for a protected operation. |
| 403 | Authenticated actor lacks role, ownership or current account access; safe disclosure may use 404 for hidden foreign resources. |
| 404 | Resource absent or intentionally hidden to prevent disclosure of foreign/unpublished data. |
| 406 | The requested `Accept` representation is unavailable for the resource. |
| 409 | Current domain state conflicts: archived new enrollment, terminal Attempt submission, conflicting idempotency replay or unmet official conditions. |
| 412 | Supplied ETag/version precondition is stale for a resource change or locked-version submission. |
| 415 | Request media type is unsupported for the selected operation. |
| 422 | Well-formed request fails field/domain validation, such as unsupported Block type or invalid evidence mapping. |
| 429 | Rate/abuse limit reached; safe retry guidance may be supplied without exposing limits or account existence. |
| 500 | Unexpected server failure; preserve authoritative state and return request ID without internal detail. |
| 503 | Required managed dependency unavailable; fail protected mutation closed and provide safe retry guidance. |

**Conditional implementation gate:** API-034 cannot settle GAP-003 mapping/target criteria; API-035 cannot settle GAP-001 revocation parameters. GAP-002 Path leave/curriculum migration has **no proposed operation**. GAP-007 exact protected-action coverage remains unset across API-010/014/017 and any other applicable official action. Existing approved core behavior is documented, but the unresolved branches are blocked for implementation. See [workflow contracts](03-api-workflows-and-failure-contracts.md) and [traceability](06-security-operations-traceability.md).

### 4.1 Shared public rules and technical choices

| Area | Bounded contract |
|---|---|
| Actor and method | All five routes are public `GET` and require no authentication. An `Authorization` header is neither needed nor a source of extra fields; no Student/Admin behavior is inferred. `GET` makes no participation, enrollment, progress, grade or completion write. Other methods return 405 with `Allow: GET`. |
| Visibility | Every list and direct lookup uses the same immutable published fixture generation. Only items marked published **and** discoverable enter API-001–004. API-005 additionally requires the requested Lesson to belong to the specified published Course version and be free for Guest. Draft, hidden and unpublished records return 404 on direct lookup and are omitted from lists/counts; no existence oracle is exposed. Archived-listing and exceptional-revocation policy remain GAP-001 and are **not modeled** by this fixture. |
| Media and content | Public Blocks contain only the listed safe rendering subset below. Markdown is sanitized to a supported safe subset before projection; browser rendering must encode text and reject unsafe links and inline HTML/script execution. Code is display text, never executable. Fixture media uses only controlled public static asset paths; no private Storage grant or browser service key. |
| Version identity | `meta.snapshotId` is the immutable fixture generation (`pub-v1`). Every Path/Course carries its own public `versionId`; a Lesson carries `courseVersionId`. For this static fixture, each is `pub-v1`, and `id` + `versionId` identifies a resource version. Path member-Course summaries, standalone Course detail, and Lessons resolve from that same generation. This does **not** decide future production publishing, latest-version selection, enrollment pinning or archived visibility. |
| Request ID and media type | `X-Request-ID` is echoed only if it matches the bootstrap's validated 1–64-character ASCII alphanumeric/`._-` form beginning with an alphanumeric; otherwise the server generates a new opaque ID. Every response has the header and `meta.requestId` or problem `requestId`. Never log a rejected header. Successful JSON uses `application/json`; problems use `application/problem+json`. Accept `application/json` or `*/*`; incompatible `Accept` receives 406. Responses use `Cache-Control: no-store` for the disposable proof. |
| Error envelope | Use API-C03/C05/C09 and §3: `{type:"about:blank", title:string, status:integer, requestId:string}` with optional safe `detail`/`invalidParams` only when no hidden identity, raw query, stack, token, private title or answer leaks. 400 invalid query/cursor/ID syntax; 404 absent/hidden/mismatched public resource; 405 method; 406 representation; 429 bounded abuse; 500 unexpected failure with no internal detail. In this all-free fixture no ordinary API-005 403 path is exercised; future approved access policy may use the original §2 403 contract. |

The following are **technical contract choices**, not Product Owner search-ranking or policy decisions. Query keys are case-sensitive. Duplicate or unknown keys, invalid UTF-8, control characters, malformed percent encoding and nonconforming values return 400. IDs are server-issued opaque strings; a URL-decoded path/filter ID must be 1–128 ASCII characters from `[A-Za-z0-9._~-]`, begin with an alphanumeric, and contain no slash, backslash or dot-segment. No client-selected version parameter exists. `q` is trimmed Unicode text of 1–100 code points; matching is case-insensitive substring matching against public title or summary after Unicode lowercase conversion, with no ranking or stemming. An absent `q` applies no text filter. This fixed behavior is sufficient for the synthetic proof and does not promise production-language search relevance.

For lists, `limit` is a decimal integer from 1 to 50 (default 20), `cursor` is an opaque URL-safe value of at most 1024 characters, and no `offset`, `sort`, unpublished-state or archive parameter is accepted. Apply visibility and all filters **before** sorting and pagination. Sort by lowercased public title ascending, then opaque canonical ID ascending; no search relevance ordering. The cursor is an authenticated, server-issued value bound to endpoint, normalized filters, limit, snapshot ID and last sort key; a process-local random signing key makes tampering fail. A cursor from another query, endpoint, fixture reset or snapshot returns 400. The signing key is never a response field or log value. `page.nextCursor` is a string when more visible records remain and `null` otherwise. The server never emits duplicates or skips visible records when the same immutable snapshot and filter set are traversed. These numeric limits and ordering are newly selected technical bounds under API-C06, not historical approved defaults.

**Response envelope:** list success is `{data: PathSummary[]|CourseSummary[], page:{nextCursor:string|null}, meta:{requestId:string, snapshotId:string, filters:object, sort:"title,id"}}`; single-resource success is `{data: PathDetail|CourseDetail|LessonDetail, meta:{requestId:string, snapshotId:string}}`. `filters` echoes only normalized, validated `q`, `courseId` or `pathId`, and effective `limit`; it never includes an untrusted raw query string or cursor. Arrays are empty when there is no match. Strings are UTF-8; counts and positions are nonnegative/positive JSON integers as specified below. No private owner, account, draft, assessment or answer field is permitted in a public DTO.

| `LessonDetail` | `id:string`, `courseId:string`, `courseVersionId:string`, `moduleId:string`, `title:string`, `position:integer`, `isFree:boolean` (true for returned fixture Lessons), `blocks:PublicBlock[]` in position order. | Draft content, answer key, graded check/Attempt, server progress, completion. |
| `PublicBlock` | `id:string`, `type:string`, `position:integer` (1-based), `payload:object` with only the type-specific fields below. | Arbitrary HTML/script, private media grant, hidden scoring/rubric/answer fields. |

The bounded `PublicBlock` union is: `richText` payload `{markdown:string}` (safe Markdown subset, no executable raw HTML or unsafe URI); `code` `{language:string, text:string}` (display only); `callout` `{text:string}`; `flashcard` `{front:string, back:string}` (public ungraded local reveal, **not** a graded assessment answer key); `media` `{src:string, alt:string}` (`src` is a controlled root-relative static asset path beginning `/assets/fixture/`, with no `//`, `..`, query or fragment). Unknown types/fields do not enter public projections. This is a VS-01A renderer proof subset, not completion of the full Q-007 authoring/rendering set for VS-05B or production VS-01B.
