## 1. Authority, scope and shared gates

Sources are the [current decisions](../DP-01/03-decision-registry.md), [DP-02 rules/AC](../DP-02/06-traceability-matrix.md), [DP-03 modules/TX](../DP-03/06-architecture-decisions-and-traceability.md), [DP-04 API/SEC/WF](../DP-04/06-security-operations-traceability.md), [DP-05 verification matrix](../DP-05/06-verification-traceability-and-defect-management.md) and [validated roadmap](01-implementation-roadmap-and-dependencies.md). AG-05 is conditionally approved for the DP-05 v0.1.0 documentation snapshot; no test has thereby passed. These are **proposed backlog contracts**, not code instructions or permissions. AG-06 is Not Approved and no slice, including VS-01A, is authorized to start. GAP-001/002/003/007 remain Open. Post-MVP features, invented delivery dates/story points and production fixture publishing are excluded. [Engineering standards](02-repository-architecture-and-engineering-standards.md), [delivery](04-secure-delivery-and-change-management.md), [gates](05-implementation-readiness-and-quality-gates.md) and [handoff](06-execution-traceability-and-handoff-register.md) are related.

**DR-001 — Definition of Ready, applied to each row:** AG-06 approved; Product Owner explicitly authorizes that **specific** slice; approved source requirement, API and SEC contracts and testable AC/DP-05 scenario are linked; named predecessors satisfied; no unresolved GAP dependency for selected behavior; schema/migration and rollback/recovery impacts reviewed; appropriate isolated development environment, fixtures and secrets available. A `Blocked` row cannot satisfy DR-001 until its GAP is explicitly disposed through change control. Neither roadmap order nor a proposed branch supplies authorization.

**DD-001 — Definition of Done, applied to each row:** implemented behavior matches the approved source, API and security contract; relevant Go unit/PostgreSQL integration/concurrency/API contract/React component/browser E2E and negative authorization tests pass; execution records include build, environment, expected/actual and reviewer; no critical regression or unauthorized contract change; docs and migration/recovery notes updated; review findings resolved and required CI checks pass. A merged PR or completed slice is **not** beta Go/No-Go approval. Each row adds its specific acceptance/negative/evidence checks to DD-001.

In the tables, `Authorization` always means implementation state, not documentation status. All UI, backend and persistence work below is **future proposed scope**; no files are created. `DoR/DoD` in every row explicitly inherit DR-001/DD-001 plus row-specific requirements.

## 4. VS-01 fixture/publishing decision boundary

VS-01A can be **planned** around versioned synthetic fixtures in disposable development environments: fixture identity, schema, content version and expected API rendering must be recorded. This makes the read contract reviewable before full CMS capability exists. It neither grants implementation permission nor creates a publish bypass. Production-compatible Guest learning in VS-01B requires a trusted Admin publish workflow (VS-05A/05B), approved published flagship content, Go visibility filtering, accessible responsive rendering and no answer leakage. Direct fixture insertion into production or a public bucket is excluded. Neither VS-01A nor VS-01B can begin until AG-06 and explicit slice authorization. A completed slice is separate from [beta release authorization](../DP-05/05-release-evidence-and-go-no-go-criteria.md).
