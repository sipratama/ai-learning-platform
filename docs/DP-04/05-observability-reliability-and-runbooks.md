`OBS` and `RB` IDs are **proposed operational contracts for AG-04 review**, not proof that a monitor, alert or drill exists. These procedures preserve Go's authoritative state. Best-effort MVP availability (INF-12) is not a commercial SLA. No numeric uptime, latency, incident response, retry-count, RPO/RTO or alert threshold is invented. FA-007 remains Open for quantitative performance and beta thresholds.

## 1. Telemetry and reliability controls

| ID | Proposed contract | Failure / verification boundary |
|---|---|---|
| OBS-001 | Emit structured JSON logs with event type, service/module, outcome, UTC time, request/correlation ID and safe reason category. | No token, profile, note, answer, raw payload or personal content. Inspect representative error logs for redaction. |
| OBS-002 | Propagate correlation ID across Go request, PostgreSQL transaction outcome, worker job and managed-provider call where feasible. | Provider IDs are mapped safely; a missing trace must not imply transaction success. Verify end-to-end request lookup. |
| OBS-003 | Measure request volume, status classes, validation/conflict rate, dependency errors, queue depth/age and resource saturation at a basic level. | Exact alert and performance thresholds remain FA-007/operational approval; verify dashboard coverage. |
| OBS-004 | Distinguish liveness from readiness: readiness fails when a required dependency or essential local state prevents safe protected operations. | Public safe reads may degrade separately; never mark official mutation ready when database authority unavailable. Test dependency failure. |
| OBS-005 | Alert on sustained Go errors, Auth/DB/Storage failures, stuck worker jobs, deletion deadline risk, migration-notice failures and unusual privileged actions. | Route to named on-call/owner in chosen operating model; no invented paging deadline. Verify sample alert receipt. |
| OBS-006 | Record minimized security audit for Admin bootstrap, publish, archive, migration, exceptional revocation, privacy deletion and privileged restore. | Audit capture must be durable where policy requires; security audit retained 180 days unless legitimate legal obligation, with no personal payload. Verify completeness/access/expiry. |
| OBS-007 | Apply bounded timeouts and cancellation to Auth/DB/Storage calls; retries only for safe/idempotent operations with backoff and bounded attempts. | Never blindly repeat unknown grade/pin/deletion outcome; read authoritative owner state first. Test timeout at each dependency. |
| OBS-008 | Use idempotency keys and owner-state reconciliation for attempts, submissions, publishing, migration and deletion work. | Duplicate delivery cannot create a second active Attempt, grade, pin or account; verify replay tests. |
| OBS-009 | Keep durable worker status, attempt count and next-retry reason without personal payload; dead/stuck work is visible for authorized repair. | Worker outage cannot reopen deleted-account access or silently complete a failed notice. Verify retry and stuck-job drill. |
| OBS-010 | Treat read projections as reconstructible. Protected commands recheck owner state; stale catalog/progress display is labeled and repairable. | No projection may issue official completion or revocation. Verify projection rebuild against owner records. |
| OBS-011 | Maintain backup/restore inventory and deletion suppression/replay evidence compatible with FA-006 B/B1. | Managed backup status alone is insufficient; demonstrate 30-day backup expiry and no resurrected personal data after isolated restore. |
| OBS-012 | Record release/incident timeline: artifact, approver, deployment, health check, rollback decision, root cause and follow-up; preserve minimized evidence. | No direct database mutation or fabricated test result; runbook execution requires authorized operator. |

**Reliability rule:** A request whose local transaction did not commit may be retried under its idempotency contract. If the outcome is unknown, first query the owner record by operation/Attempt/case ID. External Auth/Storage and learner-notice work is retry-safe but not atomic with PostgreSQL; reconciliation closes the gap. No automatic curriculum migration or unapproved revocation is inferred. See [workflow contracts](03-api-workflows-and-failure-contracts.md) and [infrastructure controls](04-infrastructure-and-deployment-operations.md).

## 2. Operational runbooks

Each row specifies symptoms, detection, containment, investigation, recovery, validation, escalation and evidence. The named role is a proposed operational owner; actual roster and alert thresholds require operating approval. Preserve request IDs, timestamps, nonpersonal audit references and configuration/artifact identity; do not copy private data into incident tickets. An authorized operator may stop unsafe actions but may not forge Student evidence or bypass an open GAP.

| ID / scenario | Symptoms and detection | Initial containment | Investigation | Recovery | Validation | Escalation and evidence |
|---|---|---|---|---|---|---|
| RB-001 Go API outage | 5xx/readiness failure and request-error alert. | Halt production rollout; keep official mutations unavailable rather than accepting unverified state. | Check recent artifact, container health, dependency errors and correlation IDs. | Restore last compatible app artifact or healthy container; preserve DB compatibility. | Public safe read and authenticated harmless read pass; no duplicate mutation. | Backend/operator owner; release ID, error timeline and rollback outcome. |
| RB-002 Supabase Auth failure | Authentication errors, key-validation failures or provider alert. | Fail protected requests closed; allow only independently safe public reads. | Check issuer/audience/key rotation, provider status and environment config without exposing secrets. | Restore trusted validation/provider connectivity or roll back faulty config through approval. | Valid token works; invalid/expired/deleted-account tokens fail; no role escalation. | Security/identity owner; redacted request IDs, key-version and provider incident record. |
| RB-003 PostgreSQL connectivity failure | Readiness fails, transaction errors, DB metric/alert. | Stop official writes; do not use browser/local records as substitute. | Check managed status, connection limits, credential/config changes and in-flight transaction outcomes. | Restore connectivity/compatible release; reconcile unknown commits by owner IDs. | Enrollment, Attempt and completion invariants hold; no duplicate grades. | Data/backend owner; transaction and dependency timeline, restore decision. |
| RB-004 Storage failure | Media/private-object errors and storage alert. | Do not expose private fallback links or mark missing learning evidence complete. | Separate public asset, private object and credential failures; inspect safe object references. | Restore provider access or approved object recovery; retry idempotent cleanup. | Allowed content works; private cross-owner access denied; deletion queue reconciled. | Storage/security owner; object class, redacted failures and recovery proof. |
| RB-005 Failed assessment submission | Student receives 409/503 or no Result after submit; conflict/error metric. | Tell client to stop blind resubmission; preserve Attempt and prior passing. | Query authoritative Attempt/Submission/Result using own scoped ID and correlation. | If committed, return same immutable Result; if active/unexpired and uncommitted, safe idempotent retry; otherwise explain terminal state. | One Result at most; no grade overwrite or pass loss. | Assessment owner; attempt state, key hash/reference and redacted trace. |
| RB-006 Stuck or expired Attempt | ACTIVE past expiry, retry mismatch or terminalization job alert. | Prevent late grading; do not force a scored failure. | Compare server expiry, locked Assessment Version and terminal history. | Apply approved expiry transition idempotently; abandonment requires GAP-003 approval, not operator guess. | Terminal history and applicable retry accounting correct; earlier pass intact. | Assessment/product owner for policy gap; state timeline without answer payload. |
| RB-007 Failed Course migration | Admin sees failed/pending migration, stale pin or notice alert. | Stop further affected migrations; preserve old pin/evidence and restrict replays. | Review authorization, source/target, mapping, audit and notice obligation; GAP-003 criteria may block. | Reconcile committed pin; retry only idempotent notice or authorized operation after policy; do not manufacture evidence. | Each affected enrollment has one intended pin, original records protected, learner notice state known. | Enrollment/product owner; migration ID, audit and notice status. |
| RB-008 Account deletion job failure | Stuck cleanup, provider error or approaching 30-day active-data target. | Keep Account access restricted; prevent self-service recovery and stop false completion. | Inspect per-owner/Auth/Storage steps, backup guard and case clock without personal payloads. | Retry failed idempotent steps; escalate policy/legal issue; reconcile individual delete or irreversible de-identification. | Active data deleted within target, backup expiry within 30 days, restore cannot resurrect, audit remains minimized. | Privacy/security owner urgently on deadline risk; case ID, step outcomes and compliance evidence. |
| RB-009 Backup restoration | Restore requested after corruption/outage; backup age/coverage review. | Restore only into isolated restricted environment; no public re-enable. | Check backup integrity, age, deletion suppression ledger and Auth/Storage consistency. | Replay/verify deletions and re-identification barriers, reconcile owner state, then authorize release. | Deleted accounts/data absent; historical active-account evidence consistent; security audit retained per policy. | Data/privacy/security owners; restore approvals, backup ID, replay and validation record. |
| RB-010 Suspected unauthorized Admin action | Unexpected publish/revoke/migrate/bootstrap or privilege alert. | Suspend affected privileged access and risky actions; preserve current evidence without silently undoing valid learning records. | Correlate minimal audit, role grants, artifact/change approval and affected resource IDs. | Revoke compromised credentials, contain affected access and use approved corrective action/change control. | Role boundary restored, affected records audited, no grade/evidence tampering. | Security/Product Owner; redacted timeline, audit integrity and decision record. |
| RB-011 Unexpected cloud cost increase | Budget alert, unusual usage/worker or storage growth. | Freeze nonessential scale/deploy changes within approved controls; keep critical deletion/security work running. | Attribute spend by environment/service, requests, retries, backup growth and resource limits. | Correct runaway job/config or scale within FA-008 B controls; seek approval for material budget/provider changes. | Alert stops, essential service and FA-006 obligations remain functional. | Operations/Product Owner; cost trend and approved remediation record, no invented budget cap. |

## 3. Governance and test boundary

Runbooks are actionable **plans**, not evidence of completed drills. FA-008 B approves basic monitoring, worker, backup and cost controls; FA-007 still owns quantitative performance and beta targets. GAP-001/002/003/007 remain Open; operators cannot use an incident to implement their missing policy. AG-04 is Not Approved, so no procedure above authorizes deployment or application code.
