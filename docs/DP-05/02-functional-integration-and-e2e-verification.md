## 1. Scope and execution convention

Sources: [DP-01 decisions](../DP-01/03-decision-registry.md), [DP-02 rules](../DP-02/02-domain-rules-and-invariants.md) and [AC](../DP-02/05-acceptance-criteria.md), [DP-03 transaction traceability](../DP-03/06-architecture-decisions-and-traceability.md), [DP-04 API](../DP-04/01-api-contract-and-resource-design.md) and [workflows](../DP-04/03-api-workflows-and-failure-contracts.md). All rows are **planned**, not passed tests. `Ready` means scenario design follows an approved boundary, **not implementation authorization**. `Conditional GAP-n` means the specified detail cannot be finalized or implemented before that GAP closes. Test in isolated project environments with synthetic data and record the [evidence fields](01-test-strategy-and-risk-based-coverage.md#5-evidence-contract-and-acceptance-implications). No post-MVP functionality, invented retry maximum or passing score is in scope.

In each row, `Evidence` specifies the required artifact *type*, never an existing artifact. `Negative` is a mandatory paired rejection check. An actor listed as Admin must be separately Go-authorized; all Student mutation data is own-scoped.

## 6. Acceptance implications

Critical E2E coverage is FT-002, FT-005–FT-009, FT-011–FT-025 and FT-027–FT-031 as applicable to approved behavior; conditional rows remain blocked for their unresolved detail. Missing P0 evidence or a failed critical journey is a [No-Go](05-release-evidence-and-go-no-go-criteria.md). Security-specific negative cases are expanded in [security verification](03-security-privacy-and-abuse-verification.md); measurement targets in [FA-007 validation](04-performance-accessibility-and-usability-validation.md); bidirectional mapping in [traceability](06-verification-traceability-and-defect-management.md). This plan does not authorize implementation or assert any execution.
