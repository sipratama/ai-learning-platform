## 1. Authority and lookup rule

Each `EXEC` row reads forward from [DP-01 decisions](../DP-01/03-decision-registry.md) → [DP-02 rules/AC](../DP-02/06-traceability-matrix.md) → [DP-03 ADR/MOD/TX](../DP-03/06-architecture-decisions-and-traceability.md) → [DP-04 API/SEC](../DP-04/06-security-operations-traceability.md) → conditionally approved DP-05 v0.1.0 [FT/ST/VAL/REL](../DP-05/06-verification-traceability-and-defect-management.md) → proposed [DP-06 backlog](03-vertical-slice-backlog-and-acceptance-contracts.md) → **future** implementation slice. Read backward by VS ID to audit its source and gate. `Evidence` denotes a required artifact type, never an existing test result. The DP-05 [later AG-05 addendum](../DP-05/06-verification-traceability-and-defect-management.md) records conditional documentation approval without changing test results. This DP-06 package is Draft, AG-06 Not Approved; **no slice is authorized, started, tested or completed**. Related documents: [roadmap](01-implementation-roadmap-and-dependencies.md), [repository standards](02-repository-architecture-and-engineering-standards.md), [delivery](04-secure-delivery-and-change-management.md), [gates](05-implementation-readiness-and-quality-gates.md).

## 3. Handoff register template and current state

`HAND-001` is the future per-slice handoff record. It must contain: VS ID and scope; exact approved baseline and version; predecessors and proof; open blockers/GAP disposition; required environment and fixture; **proposed** branch name (not created); expected UI/Go/persistence/docs deliverables; affected RULE/AC/ADR/MOD/TX/API/SEC/FT/ST/VAL IDs; negative/security/privacy and migration/recovery considerations; Product Owner AG-06 and **slice-specific** authorization reference; implementation status; review/CI status; evidence IDs/artifact locations; reviewer and next decision. Record actual dates and signatures only when an event occurs. Current state for every VS ID in §2: `Product Owner authorization = Pending`, `implementation = Not started`, `review = Not run`, `evidence = None`; policy-dependent rows additionally `GAP blocker = Open`. No branch is created by listing a proposed name.

| ID | Handoff completeness check |
|---|---|
| HAND-002 | Before implementation, resolve applicable GAP, confirm DR-001 and record explicit Product Owner slice authorization. A roadmap row or AG-06 alone is insufficient. |
| HAND-003 | During implementation, link code/PR only after authorized Git action, track contract changes, preserve immutable evidence and defects. Do not report a planned FT/ST case as executed. |
| HAND-004 | At slice completion, verify DD-001 with real CI/integration/security evidence and reviewer; keep beta release separate under DP-05 GATE-001–007. |

Historical EG-001–EG-003 remain source-evidence limitations under AG-01-EG-B, not new requirements. The current [Open Decisions Register](../DP-01/04-open-decisions-register.md) owns GAP status. No beta release, application work or Git write is authorized by this traceability document.
