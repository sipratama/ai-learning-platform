## 1. Exact count and current applicability

Fresh [full audit](evidence/2026-11-01-decision-readiness/npm-audit.json) exits **1** with **11 Moderate, 0 High/Critical**; [production-only audit](evidence/2026-11-01-decision-readiness/npm-audit-production.json) exits **0** with zero reported findings. [Execution times](evidence/2026-11-01-decision-readiness/npm-audit-execution.json), [production timing](evidence/2026-11-01-decision-readiness/npm-audit-production-execution.json), [resolved tree](evidence/2026-11-01-decision-readiness/npm-tree.json) and [individual machine-readable assessments](evidence/2026-11-01-decision-readiness/advisory-applicability.json) identify the unchanged graph.

The 11 entries are **one root advisory plus ten inherited package/metavulnerability entries**, not 11 independent CVEs. All affected installed nodes are development-only in the lockfile. The root [GHSA-g3hv-75wg-m249 / CVE-2026-118764](https://github.com/advisories/GHSA-g3hv-75wg-m249) covers `minimatch <11.0.1`; the published patch is `11.0.1`. Its described amplification requires attacker-controlled glob patterns with `optimizationLevel >= 2`. The [maintainer patch](https://github.com/isaacs/minimatch/commit/77a0f5c) bounds the problematic preprocessing.

Local caller inspection found ESLint and config-array using `{dot: true}` without setting that optimization option; typescript-estree's `allowDefaultProject` matcher does likewise. Installed minimatch defaults to optimization level **1**. The checked application config contains static ignore patterns and recommended presets, without `parserOptions.projectService`/`allowDefaultProject`. **Inference:** the advisory's specific high-optimization path is not demonstrated in those inspected callers/current configuration. This is a bounded source assessment, not proof of nonreachability across all dependencies/configuration or a basis to suppress the audit. No denial-of-service payload was executed.

A contributor can change repository tooling/configuration before CI, and development processes execute with local permissions. CI uses read-only repository permissions and job timeouts, but neither prevents CPU/memory exhaustion nor turns untrusted executable config into safe input. Production-only audit has narrower scope; it does not certify built bundles or justify accepting tooling risks. Root source/caller hashes and exact dependency/peer edges are retained in the assessment JSON.
